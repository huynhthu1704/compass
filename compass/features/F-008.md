# F-008 · Compass follows its own delivery process

**Business intent:** From the next pull request on, 100% of Compass's own pull requests go intent → requirements → design → plan → checks and independent review (today: none are checked). · [intent](../intent/F-008.md) · [design](../design/F-008.md)

## Problem
Compass enforces this process in other projects but not in its own code: no CI on pull requests, no tests, no plan and no review record.

## Users
- Product Owner
- Developer
- AI agents

## Outcome metric
Share of Compass PRs checked by CI and independently reviewed: 0% → 100% from the first PR after setup.

## In scope
- Framework in the repo
- CI on every PR
- Tests for the checking scripts
- No drift between compass/ and src/framework/

## Out of scope
- Requirements for every existing behaviour
- Changing the website deploy

## Risks
- The setup PR is larger than 12 files (the check starts after it)

## Requirements
- **REQ-001** The Compass repo has the Compass Framework — In build (Must)
- **REQ-002** Every pull request is checked by CI — In build (Must)
- **REQ-003** The checking scripts have unit tests — Approved (Must)
- **REQ-004** The installed scripts never drift from the portal's copies — Approved (Must)

## Test cases
- **TC-001** Framework files present and generated by frameworkFiles() → REQ-001 · Not run
- **TC-002** CI runs the spec check, guardrails, tests and build on a PR → REQ-002 · Not run
- **TC-003** Unit tests for check-spec, the plan check and the edit hook → REQ-003 · Not run
- **TC-004** compass/*.mjs identical to src/framework/ → REQ-004 · Not run

# F-011 · Readability follow-ups: status labels and phone stage strip

**Business intent:** The Product Owner tells Draft from Approved labels without reading them, and no word breaks in a feature's stage strip on a 390 px phone (today: both labels honey; words break mid-word). · [intent](../intent/F-011.md) · [design](../design/F-011.md) (Approved)

## Problem
After the honey rebrand, Draft (warning) and Approved (brand) labels are both honey; on phones the six stage cards of a feature page squeeze into narrow columns and break words.

## Users
- Product Owner
- Everyone reviewing requirements and tests

## Outcome metric
Draft vs Approved: same colour family → different families (test); broken words in the stage strip at 390 px: several → 0 (screenshot).

## In scope
- Status label colours on requirements, test cases and features
- Stage strip layout below 720 px

## Out of scope
- Other label colours
- A redesign of the feature page

## Risks
- Tokens of the honey design system only; no new libraries
- WCAG AA contrast kept
- Desktop stage strip unchanged

## Requirements
- **REQ-013** Draft and Approved labels look different at a glance — Approved (Must)
- **REQ-014** The stage strip of a feature reads well on a phone — Approved (Should)
- **REQ-015** Pages use up to 1600 px on large screens and stay responsive — Approved (Should)

## Test cases
- **TC-023** Draft is neutral, Approved is mint → REQ-013 · Not run
- **TC-024** Status label contrast → REQ-013 · Not run
- **TC-025** Stage strip on a 390 px phone → REQ-014 · Not run
- **TC-026** Desktop stage strip unchanged → REQ-014 · Not run
- **TC-027** Content width up to 1600 px with fluid padding → REQ-015 · Not run
- **TC-028** No sideways scrolling at 1920, 1280 and 390 px → REQ-015 · Not run

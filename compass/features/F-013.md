# F-013 · Auto-sync never overwrites a newer spec on GitHub

**Business intent:** No spec commit from the portal ever lands on a version of compass/spec.json the portal has not seen, and no save quietly removes requirements, tests or decisions (today: one stale browser copy turned 107 requirements into 1 on Bee There's main). · [intent](../intent/F-013.md) · [design](../design/F-013.md)

## Problem
Auto-sync commits the portal's local copy of compass/spec.json without checking GitHub first, and stores the commit id instead of the file's version, so a stale copy overwrote Bee There's spec on 2026-11-26.

## Users
- Product Owner
- Agents and people who edit compass/spec.json

## Outcome metric
Spec commits on top of an unseen version: possible → 0 (unit test replays the incident); items silently removed by a save: 103 on 2026-11-26 → 0.

## In scope
- Version check before every spec commit (auto-sync, Commit spec, release)
- Stop-and-ask banner with Load GitHub's version / Keep both
- Fresh copy on opening a project
- Refuse saves that remove items not deleted in the portal
- Read a design tool stored as a plain link

## Out of scope
- Real-time collaboration or locking
- Overwriting GitHub with the portal's copy
- Restoring other projects

## Risks
- No new libraries, no server
- Demo projects unchanged
- Bee There keeps designTool as a plain link string (its tests require it)

## Requirements
- **REQ-020** The portal checks GitHub's version before every spec commit — Draft (Must)
- **REQ-021** When GitHub has a newer spec, the portal stops and asks — Draft (Must)
- **REQ-022** Opening a project loads the latest spec from GitHub first — Draft (Should)
- **REQ-023** A spec commit never removes items quietly — Draft (Must)
- **REQ-024** A design tool stored as a plain link is read correctly — Draft (Could)

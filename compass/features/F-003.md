# F-003 · Design: design tool and approval gate

**Business intent:** No code is written before the PO/UX approve a design traced to the requirements. · [intent](../intent/F-003.md) · [design](../design/F-003.md)

## Problem
Code built before anyone agreed on the screens has to be redone.

## Users
- UX / Designer
- Product Owner

## Done when
Build is locked until the design is Approved (baseline).

## In scope
- One design tool per project (Figma…)
- Design agent drafts screens ↔ REQ ids
- Approve design unlocks Build

## Out of scope
- _(none yet)_

## Risks
- _(none yet)_

## Requirements
- **REQ-103** Design: design tool, screens and approval gate — Done (Must)
- **REQ-025** Figma components on the Components page, one section per feature — Done (Should)
- **REQ-080** The admin links the project's Figma file and Miro board on a Project settings page — Approved (Must)
- **REQ-081** Every Design page keeps the preview in focus and shows the design files behind a button — Approved (Must)
- **REQ-082** Projects with the old single design link keep working, and agents name both files — Approved (Must)
- **REQ-114** The Design agent saves each screen as a layout the Figma plugin can draw — Draft (Must)
- **REQ-115** The Compass Figma plugin signs in to Compass, and only UX, PO or Admin can start a drawing run — Draft (Must)
- **REQ-116** The plugin's Design agent draws every screen from the file's design system with a fixed set of tools — Draft (Must)
- **REQ-117** The agent checks an image of each drawn screen and fixes what it finds — Draft (Should)
- **REQ-118** The plugin saves the frame links to compass/spec.json, and the Design page shows them — Draft (Must)
- **REQ-119** Running the plugin again after a Redesign redraws only the screens that changed — Draft (Should)
- **REQ-120** Approving a design starts the Test design agent — Draft (Should)

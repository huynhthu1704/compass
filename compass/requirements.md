## REQ-001 · The Compass repo has the Compass Framework
As the product owner, I want the Compass repo to carry the same Compass Framework it installs into other projects, generated by the portal itself, so that any person or agent changing Compass follows the same process.

**Priority:** Must · **Status:** In build

**Acceptance criteria**

_AC1_
```gherkin
Given the Compass repository
When I open it
Then it has compass/ (spec.json, intent/, design/, plans/, REVIEW.md, guardrails.json and the checking scripts), AGENTS.md, CLAUDE.md, the PR and issue templates and the Claude Code edit hook
```

_AC2_
```gherkin
Given the framework files in the repo
When they are compared with what the portal generates for this project
Then they were produced by the portal's own frameworkFiles(), not written by hand
```

## REQ-002 · Every pull request is checked by CI
As the product owner, I want every pull request to Compass checked automatically, so that a change without approvals, a plan or tests cannot be merged unnoticed.

**Priority:** Must · **Status:** In build

**Acceptance criteria**

_AC1_
```gherkin
Given a pull request to main
When CI runs
Then it runs the spec check, the guardrails check (main's copy, including the plan check), the unit tests and the build
```

_AC2_
```gherkin
Given a push to main
When the existing deploy workflow runs
Then the website deploy works exactly as before
```

## REQ-003 · The checking scripts have unit tests
As the product owner, I want the checking scripts that Compass installs into every project to have their own tests, so that a broken check is caught before it reaches other projects.

**Priority:** Must · **Status:** Approved

**Acceptance criteria**

_AC1_
```gherkin
Given the scripts in src/framework/
When npm test runs (Node's built-in runner, no new library)
Then it covers the spec check (traceability, intent, design gate), the plan check and the edit hook's decisions
```

_AC2_
```gherkin
Given a change that breaks one of these checks
When npm test runs
Then at least one test fails
```

## REQ-004 · The installed scripts never drift from the portal's copies
As the product owner, I want the checking scripts in the repo's compass/ folder to stay identical to the copies the portal installs (src/framework/), so that Compass is checked by exactly the rules it gives other projects.

**Priority:** Must · **Status:** Approved

**Acceptance criteria**

_AC1_
```gherkin
Given compass/check-spec.mjs, compass/check-guardrails.mjs, compass/guardrails-lib.mjs and compass/hooks/guard-edit.mjs
When one differs from its copy in src/framework/
Then npm test fails and names the file
```

## REQ-101 · Idea: business need revised into a business intent
As a product owner, I want to write a business need and get it revised into a measurable business intent, so that the work starts from an outcome.

**Priority:** Must · **Status:** Done

**Acceptance criteria**

_AC1_
```gherkin
Given a business need on the Idea page
When the Ideation agent runs and I approve its brief
Then the feature has the revised intent, my original need and a brief, and the Requirements agent starts
```

## REQ-102 · Requirements: generate and approve
As a business analyst, I want requirements drafted with Given/When/Then criteria, so that I only review and approve them.

**Priority:** Must · **Status:** Done

**Acceptance criteria**

_AC1_
```gherkin
Given an approved intent
When the Requirements agent runs and its proposal is accepted
Then Draft requirements appear; approving the last one starts the Design agent
```

## REQ-103 · Design: design tool, screens and approval gate
As a product owner, I want a design traced to the approved requirements and approved before coding, so that code is built to agreed screens.

**Priority:** Must · **Status:** Done

**Acceptance criteria**

_AC1_
```gherkin
Given a feature whose design is not Approved
When I open Build
Then coding is locked; after Approve design it is unlocked
```

## REQ-104 · Test cases: one or more per requirement
As QA, I want test cases generated for every uncovered requirement, so that nothing is built untested.

**Priority:** Must · **Status:** Done

**Acceptance criteria**

_AC1_
```gherkin
Given requirements without test cases
When the Test design agent runs and its proposal is accepted
Then each of them has a happy-path and a negative test case
```

## REQ-105 · Build: coding agent, plan file and pull request
As a developer, I want the coding agent to propose a change set that passes guardrails and opens a PR with a plan file, so that I only review the diff.

**Priority:** Must · **Status:** Done

**Acceptance criteria**

_AC1_
```gherkin
Given approved requirements and an approved design
When I approve the agent's change set
Then a branch and PR are opened with compass/plans/<REQ-ids>-<name>.md committed first
```

## REQ-106 · Release: merge, tag and deploy
As a delivery manager, I want to release several features in one confirmed step, so that releases are consistent.

**Priority:** Must · **Status:** Done

**Acceptance criteria**

_AC1_
```gherkin
Given approved agent PRs with green CI
When I confirm the release
Then they are merged, requirements are marked Done and a vX.Y.Z tag is created
```

## REQ-107 · Framework: install into repos without overwriting their own files
As a repo owner, I want Install framework to add only missing files, so that my repo's own scripts and docs are kept.

**Priority:** Must · **Status:** Done

**Acceptance criteria**

_AC1_
```gherkin
Given an existing repo with its own compass/*.mjs
When Install framework runs
Then only missing framework files are added, the generated spec views are refreshed and the repo's own files are listed as kept
```

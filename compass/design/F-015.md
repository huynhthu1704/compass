## Approach
People sign in on a single centred card ("Sign in to Compass" + "Sign in with Google"); a Google account on no team lands on "You have no access yet" with its email, Reload and Sign out, and no project data. Inside a project, Admins and the super admin get a new "Team" item in the sidebar (after Release). The Team page has three cards: Add person (email + role checkboxes PO, BA, UX, QA, Dev, DM, Ops, Admin; several can be ticked), the team list (email, role chips, Edit roles, Remove; the only Admin cannot be removed) and, before phase 1, the project GitHub token (removed by REQ-043, see SCR-9). Each gate card on a feature page shows its button enabled for the signed-in person's roles and greyed out with "Needs the <role> role" otherwise; approvals show "Approved by <email> (<role>)"; an approval that Firebase does not confirm shows a red "Unconfirmed" badge. The sidebar account card shows the Google email; its account menu (REQ-110, ADR-019) has Sign out and, for super admins, Connections and the role picker shows "My roles: …". On phones the Team page stacks the cards, role checkboxes wrap, and Edit roles / Remove move into a ⋮ menu per row. With sign-in on, the "What's your role?" onboarding screen is not shown: roles come from the team. Someone on no team can "Try the demo" from the no-access screen (ADR-019 removed it from the sidebar): they pick one or more roles on the existing role screen and see the sample projects with a honey "Demo" banner and a demo roles menu (honey checkboxes) in the sidebar (REQ-121). Phase 1 (REQ-041–REQ-046): the project GitHub token card is removed from the Team page on desktop and phone (SCR-9); super admins set a shared work token on Connections (SCR-11).

### SCR-1 · Desktop · Sign in with Google
**Elements:** Compass brand; Title "Sign in to Compass" and the line "Sign in with your Google account. You'll see the projects your team added you to, or you can try the demo." (ADR-024); Button "Sign in with Google" (Google logo, full width); Demo-mode note

**States:** Signing in → button shows a spinner; Popup closed or blocked → message under the button; Demo mode (no Firebase) → this screen is skipped

### SCR-2 · Desktop · No access yet
**Elements:** Title "You have no access yet"; "Signed in as <email>"; Explanation to ask the admin; Reload (primary), Try the demo (secondary) and Sign out; No project names or data

**States:** Unverified email → same screen; After the admin adds the email → Reload opens the Projects page; Try the demo → the existing "What's your role?" screen, then the demo (SCR-7)

### SCR-3 · Desktop · Team page
**Elements:** Sidebar from the approved sidebar design with a new "Team" item; account card with the Google email (its menu has Sign out); "My roles: …"; Card Add person: Google account email, role checkboxes PO, BA, UX, QA, Dev, DM, Ops, Admin, Add person button and rules hint; Card Team (n): rows with email, role chips, Edit roles, Remove; Only Admin row: "Only Admin — cannot be removed", Remove disabled; Card Project GitHub token: status badge with expiry, masked token, Test, Replace token, fine-grained token help; Honey notice after removing someone: replace the token

**States:** Bad email, no role or duplicate → inline error, list unchanged; Email saved trimmed and in lower case; Super admin ticking Admin → that person manages this project only; Token missing or expired → red badge "Missing or expired"; Not an Admin → page not in the menu, token never shown; Project with no team yet → only the super admin sees Add person; saving creates the first team and the approval baseline; Phase 1: the Project GitHub token card and its states are removed (REQ-043, SCR-9)

### SCR-4 · Desktop · Gates follow my roles
**Elements:** "Signed in as <email>" with role chips; Gate cards: Intent, Requirements, Design, Test cases, Build, Release; Enabled button (honey) with "Your <role> role can approve…"; Disabled button (grey) with "Needs the <role> role"; Approved gate: badge and "Approved by <email> (<role>) · date"; Red notice "Not allowed for your roles" when Firestore refuses; Red "Unconfirmed" badge on an approval with no Firebase record, naming who it claims; Notice on the Feature board listing unconfirmed approvals with links

**States:** Super admin → every gate enabled; Demo mode → gates as today, approvedBy unchanged; Firestore refuses the approval record → red notice, nothing committed; Approval in neither the baseline (approvals that existed when the team was created) nor a Firebase record → Unconfirmed badge, whatever date it claims

### SCR-11 · Desktop · Connections for super admins
**Elements:** Header: only super admins see this page; the work token and key are used by everyone on your teams; Card GitHub: work token (masked; fine-grained, Compass repositories only; Contents, Pull requests, Issues, Workflows and Pages: Read and write; Actions: Read; never Administration; Compass cannot check that Administration is off; switching GitHub Pages on uses the creator token), "GitHub account for new projects" (e.g. huynhthu1704), "Creator token — this device only" (masked; all repositories and Administration; never shared), Save & test; Card Anthropic (agents): badge "Used by everyone on your teams", API key (masked); without it agents run in demo mode; Honey notice: every member's browser can read the work token and key; limit them, give the key a spending limit, replace both when someone leaves; Model and Sync settings: saved for everyone on the teams

**States:** Creator token missing → New project says "Add a creator token on Connections"; Work token cannot reach a project's repository → "Add <repo> to the work token on GitHub"; Not a super admin → no link to this page; its address goes to Projects

## Notes
Components: local "F-015 / Button" (Primary, Secondary, Danger, Disabled), "F-015 / Role chip" and "F-015 / Role checkbox", bound to the Compass color variables and text styles (Lexend headings, Be Vietnam Pro body). Keyboard: role checkboxes are real checkboxes in one group with a legend; disabled gate buttons keep their hint as aria-describedby so screen readers say which role is needed; the ⋮ menu on phones is a button with a menu. Text colours from honey tokens only. The sidebar reuses the approved sidebar design; only the Team item and account card text change. The brand block uses the Logo / Compass component from the Components page. Phase 1 (REQ-041–REQ-046, ADR-016–018): Connections (SCR-11) is for super admins only: the work token, the GitHub account for new projects, the Anthropic key and the model and sync settings are saved for everyone on the teams; the creator token stays on the super admin's device. Commits and pull requests end with "Made in Compass by <email> (<role>)" (REQ-042, no screen). SCR-8 to SCR-11 approved by the Product Owner in chat on 2026-11-28. SCR-7 roles control changed to a checkbox menu by REQ-121 (approved by the Product Owner in chat on 2026-11-28, ADR-025); the Figma frame is still the single dropdown.

## Approach
People sign in on a single centred card ("Sign in to Compass" + "Sign in with Google"); a Google account on no team lands on "You have no access yet" with its email, Reload and Sign out, and no project data. Inside a project, Admins and the super admin get a new "Team" item in the sidebar (after Release). The Team page has three cards: Add person (email + role checkboxes PO, BA, UX, QA, Dev, DM, Ops, Admin; several can be ticked), the team list (email, role chips, Edit roles, Remove; the only Admin cannot be removed) and the project GitHub token (masked, Test, Replace, fine-grained token help, and a reminder to replace it after removing someone). Each gate card on a feature page shows its button enabled for the signed-in person's roles and greyed out with "Needs the <role> role" otherwise; approvals show "Approved by <email> (<role>)"; an approval that Firebase does not confirm shows a red "Unconfirmed" badge. The sidebar account card shows the Google email (its menu has Sign out) and the role picker shows "My roles: …". On phones the Team page stacks the cards, role checkboxes wrap, and Edit roles / Remove move into a ⋮ menu per row. With sign-in on, the "What's your role?" onboarding screen is not shown: roles come from the team. Someone on no team can "Try the demo" from the no-access screen (team members from the sidebar account menu): they pick a role on the existing role screen and see the sample projects with a honey "Demo" banner and a demo role picker in the sidebar.

### SCR-1 · Desktop · Sign in with Google
**Elements:** Compass brand; Title "Sign in to Compass" and the email-matching hint; Button "Sign in with Google" (Google logo, full width); Hint "No account yet? Ask your project Admin…"; Demo-mode note

**States:** Signing in → button shows a spinner; Popup closed or blocked → message under the button; Demo mode (no Firebase) → this screen is skipped

### SCR-2 · Desktop · No access yet
**Elements:** Title "You have no access yet"; "Signed in as <email>"; Explanation to ask the admin; Reload (primary), Try the demo (secondary) and Sign out; No project names or data

**States:** Unverified email → same screen; After the admin adds the email → Reload opens the Projects page; Try the demo → the existing "What's your role?" screen, then the demo (SCR-7)

### SCR-3 · Desktop · Team page
**Elements:** Sidebar from the approved sidebar design with a new "Team" item; account card with the Google email (its menu has Sign out); "My roles: …"; Card Add person: Google account email, role checkboxes PO, BA, UX, QA, Dev, DM, Ops, Admin, Add person button and rules hint; Card Team (n): rows with email, role chips, Edit roles, Remove; Only Admin row: "Only Admin — cannot be removed", Remove disabled; Card Project GitHub token: status badge with expiry, masked token, Test, Replace token, fine-grained token help; Honey notice after removing someone: replace the token

**States:** Bad email, no role or duplicate → inline error, list unchanged; Email saved trimmed and in lower case; Super admin ticking Admin → that person manages this project only; Token missing or expired → red badge "Missing or expired"; Not an Admin → page not in the menu, token never shown; Project with no team yet → only the super admin sees Add person; saving creates the first team and the approval baseline

### SCR-4 · Desktop · Gates follow my roles
**Elements:** "Signed in as <email>" with role chips; Gate cards: Intent, Requirements, Design, Test cases, Build, Release; Enabled button (honey) with "Your <role> role can approve…"; Disabled button (grey) with "Needs the <role> role"; Approved gate: badge and "Approved by <email> (<role>) · date"; Red notice "Not allowed for your roles" when Firestore refuses; Red "Unconfirmed" badge on an approval with no Firebase record, naming who it claims; Notice on the Feature board listing unconfirmed approvals with links

**States:** Super admin → every gate enabled; Demo mode → gates as today, approvedBy unchanged; Firestore refuses the approval record → red notice, nothing committed; Approval in neither the baseline (approvals that existed when the team was created) nor a Firebase record → Unconfirmed badge, whatever date it claims

### SCR-5 · Phone · Sign in with Google
**Elements:** Brand; Title and hint; Full-width Sign in with Google button; No-account hint

**States:** Same states as SCR-1

### SCR-6 · Phone · Team page
**Elements:** Top bar with menu and project name; Add person card: email, wrapping role checkboxes, full-width Add person; Team list rows: email, role chips, ⋮ menu (Edit roles, Remove); Token row: status and Manage (opens the token card)

**States:** Same states as SCR-3; No sideways scrolling at 390 px

### SCR-7 · Desktop · Demo after sign-in
**Elements:** Honey banner "Demo — sample data, kept in this browser only" with "Leave demo"; Sidebar role picker "Demo role: QA ▾" (only in the demo); Account card with the Google email; its menu has Leave demo and Sign out; Sample project (Travel Journal) as today

**States:** Leave demo → back to the projects, or to "You have no access yet"; No Firebase or GitHub call while in the demo

## Notes
Components: local "F-015 / Button" (Primary, Secondary, Danger, Disabled), "F-015 / Role chip" and "F-015 / Role checkbox", bound to the Compass color variables and text styles (Lexend headings, Be Vietnam Pro body). Keyboard: role checkboxes are real checkboxes in one group with a legend; disabled gate buttons keep their hint as aria-describedby so screen readers say which role is needed; the ⋮ menu on phones is a button with a menu. Text colours from honey tokens only. The sidebar reuses the approved sidebar design; only the Team item and account card text change. The brand block uses the Logo / Compass component from the Components page.

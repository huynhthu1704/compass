# Intent: Auto-sync never overwrites a newer spec on GitHub

Status: Approved (idea brief approved in the Compass portal)
Requested: 2026-11-26 for feature F-013, in the Compass portal

_Generated from `compass/spec.json → features[F-013].idea`. Edit the idea there or in the portal, not this file._

## What we want
No spec commit from the portal ever lands on a version of compass/spec.json the portal has not seen, and no save quietly removes requirements, tests or decisions (today: one stale browser copy turned 107 requirements into 1 on Bee There's main).

_Business need as the Product Owner wrote it:_ Fix the cause in Compass: before auto-sync commits, it should check that main hasn't changed since the portal last read it. If it has, it should stop and ask instead of overwriting.

## Why
Auto-sync commits the portal's local copy of compass/spec.json without checking GitHub first, and stores the commit id instead of the file's version, so a stale copy overwrote Bee There's spec on 2026-11-26.

## Constraints
- No new libraries, no server
- Demo projects unchanged
- Bee There keeps designTool as a plain link string (its tests require it)

## Success measure
Spec commits on top of an unseen version: possible → 0 (unit test replays the incident); items silently removed by a save: 103 on 2026-11-26 → 0.

## Out of scope
- Real-time collaboration or locking
- Overwriting GitHub with the portal's copy
- Restoring other projects

## Requirements
- REQ-020 — The portal checks GitHub's version before every spec commit
- REQ-021 — When GitHub has a newer spec, the portal stops and asks
- REQ-022 — Opening a project loads the latest spec from GitHub first
- REQ-023 — A spec commit never removes items quietly
- REQ-024 — A design tool stored as a plain link is read correctly

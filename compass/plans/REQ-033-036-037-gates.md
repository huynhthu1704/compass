# Plan: REQ-033, REQ-036, REQ-037 Gates follow my roles; approvals recorded in Firebase first

Feature: F-015 · Requirements: REQ-033 (AC1–AC4), REQ-036 (AC1 for requirements and designs), REQ-037 (AC1–AC3; AC4 is
the merged rules) · Test cases: TC-066, TC-071, TC-072 · Intent: compass/intent/2026-11-27-team-access.md · Design: compass/design/F-015.md (SCR-4) · ADR-012

Seventh build step of F-015. With sign-in on, every approval gate — approve a requirement (or all), approve a design,
approve an agent run (idea → intent, requirements, design, test cases, code → build) and release — is enabled only for a
person whose roles own the gate (or the super admin), shows "Needs the … role" otherwise, writes an approval record to
Firestore before anything else, and records `approvedBy` as "<email> (<role>)". With sign-in off nothing changes. Still
off on the live site. The Unconfirmed badge (REQ-038), "My roles" (REQ-039) and the demo after sign-in (REQ-040) follow
in the next PR.

- `compass/plans/REQ-033-036-037-gates.md` — this plan

## Steps
1. Plan (first commit). 2. `gateForAgent` + test. 3. `approvals.ts`, Firebase record. 4. Harness and pages. 5. Checks,
emulator run (BA: requirements yes, design no; Firestore record written; a forged page write refused), PR.

## Scope note (first review)
- `approvedBy` / `approvedAt` are written to spec.json for requirements and designs. Intent, test-case and release
  approvals are recorded in Firebase and in the run trace ("by <email> (<role>)") but have no spec.json field yet: they
  follow in the next PR (with REQ-038, which needs them to flag unconfirmed approvals).
- The requirement Status field is gated too: leaving Draft is a recorded approval; going back to Draft clears approvedBy.
- A demo-mode coder run on a real repo needs the Dev role and writes a `build` record even though nothing is pushed:
  intended — the gate is about who may approve, and records are append-only.

## Risks
- A record is written but the later GitHub step fails → the record stays (append-only) and a retry writes another; the
  Unconfirmed check (next PR) matches on item, gate, email and role, so extra records are harmless.
- Demo projects, local projects and sign-in off → no record, today's behaviour and `approvedBy` text.
